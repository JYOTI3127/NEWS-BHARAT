# Hostinger Auto Deploy Setup

This project should not deploy the source repo directly to Hostinger because the live site is generated by:

```bash
npm run build
```

That command runs:

```bash
vite build && node prerender.mjs
```

The GitHub Actions workflow at `.github/workflows/deploy-hostinger.yml` builds the site on GitHub and uploads only the `build/` output to Hostinger.

## GitHub secrets to add

Add these repository secrets in GitHub:

- `HOSTINGER_FTP_SERVER`
- `HOSTINGER_FTP_USERNAME`
- `HOSTINGER_FTP_PASSWORD`
- `HOSTINGER_FTP_PORT`
- `HOSTINGER_FTP_PROTOCOL`
- `HOSTINGER_SERVER_DIR`
- `VITE_API_TARGET`

Recommended values:

- `HOSTINGER_FTP_PORT`: `21` for FTP or `990` for FTPS
- `HOSTINGER_FTP_PROTOCOL`: `ftp` or `ftps`
- `HOSTINGER_SERVER_DIR`: `/public_html/`
- `VITE_API_TARGET`: `https://news4bharat.cloud`

## What triggers deployment

The workflow runs on:

- push to `main`
- manual run from GitHub Actions
- `repository_dispatch` with these event types:
  - `article-published`
  - `article-updated`
  - `rebuild-frontend`

## What backend needs to trigger

Backend should call the GitHub repository dispatch API after article publish/update:

```bash
POST https://api.github.com/repos/JYOTI3127/NEWS-BHARAT/dispatches
```

Headers:

```text
Authorization: Bearer <GITHUB_TOKEN>
Accept: application/vnd.github+json
Content-Type: application/json
```

Body:

```json
{
  "event_type": "article-published"
}
```

`event_type` can also be `article-updated` or `rebuild-frontend`.

## Important note

This setup means:

- frontend code changes deploy automatically on push to `main`
- article publish/update can also trigger a rebuild without manual redeploy
- backend does not need to generate frontend HTML itself

Backend still needs one small integration: it must trigger the GitHub dispatch request when an article is published or updated.
